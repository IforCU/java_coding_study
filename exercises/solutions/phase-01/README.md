# Phase 1 정답과 해설

이 디렉터리는 출금 가능 정책 과제를 직접 해결한 뒤 비교하는 자료입니다. 정상 실행 모듈과 기본 Maven 빌드에는 포함되지 않습니다.

## 조건을 나눈 이유

정답은 먼저 null, 음수 잔액, 0 이하 출금액을 거절합니다. 다음으로 두 입력이 원 단위의 정수 값인지 확인하고, 마지막으로 잔액이 출금액 이상인지 비교합니다. 검증할 수 없는 입력은 예외 대신 `false`를 반환하는 것이 이 실습의 계약입니다.

`stripTrailingZeros()`로 불필요한 소수부 0을 제거한 뒤 scale을 보면 `100.00`과 `100.1`을 구분할 수 있습니다. 전자는 수학적으로 정수지만 후자는 아닙니다. scale이 음수인 `1E+3`도 정수이므로 허용합니다. 반올림으로 `100.1`을 `100`으로 바꾸지 않습니다.

`compareTo()`는 scale이 달라도 수치로 비교합니다. `equals()`는 `100`과 `100.00`을 다르게 볼 수 있으므로 이 금액 비교에 쓰지 않습니다. `double`이나 `long`으로 변환하지 않아 큰 금액의 정밀도 손실과 범위 초과도 피합니다. 입력 `BigDecimal`은 변경하지 않습니다.

이 메서드는 실제 출금이나 거래 내역 생성을 수행하지 않습니다. 메모리 계좌 모듈의 `BankService.withdraw`가 수행하는 상태 변경과 분리된 순수한 판단 함수입니다.

## 선택 실행

프로젝트 루트에서 정답 프로필을 명시합니다.

```sh
mvn -Dmaven.repo.local=.cache/maven-repository -Psolution-phase1 -pl exercises/solutions/phase-01 -am verify
```

`solution-phase1` 모듈은 starter의 계약 테스트 소스를 함께 사용합니다. 따라서 학습자가 테스트를 삭제하거나 기대값을 변경해 통과시키면 정답 검증의 의미도 달라집니다. 테스트는 보존하고 구현을 비교하세요. 성공 기대값과 실제 실행 기록은 구분하며 실제 결과는 루트 `PROGRESS.md`에 남깁니다.
