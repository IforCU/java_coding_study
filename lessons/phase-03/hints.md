# Phase 3 — 단계별 힌트

## 1. Mapper 연결 이름 확인

namespace는 인터페이스의 전체 이름이고 statement ID는 메서드 이름과 연결됩니다. XML이 문법적으로 유효해도 이름이 다르면 필요한 statement를 찾지 못할 수 있습니다.

## 2. 필수 조건과 선택 조건 구분

날짜가 없는 검색에서도 다른 계좌의 거래가 섞이면 안 됩니다. 네 가지 테스트에서 항상 필요한 조건과 상황에 따라 추가되는 조건을 따로 표시해 보세요.

## 3. null과 누락

Map에 키가 없는 경우와 값이 null인 경우 모두 선택 날짜가 없는 상태로 다룹니다. 빈 문자열을 날짜 값으로 넣는 계약은 아닙니다. 이미 타입이 정해진 OffsetDateTime이 입력됩니다.

## 4. XML과 SQL 문법

SQL의 비교 연산자와 XML의 특수문자가 겹칠 수 있습니다. XML 파싱 단계에서 실패한다면 DB 설정을 바꾸기 전에 해당 문자가 XML에서 어떻게 표현되는지 확인하세요. 날짜 조건은 시작 포함·끝 제외입니다.

## 5. 바인딩과 문자열 치환

BoundSql에는 입력값 자체 대신 PreparedStatement 자리표시자가 남아야 합니다. XML을 읽고 값이 SQL 텍스트에 붙는 방식인지, 바인딩 정보로 전달되는 방식인지 구분합니다. 문자열을 따옴표로 감싼다고 값 바인딩이 되는 것은 아닙니다.

## 6. 검증 범위를 구분

바인딩 테스트가 성공해도 PostgreSQL이 그 SQL과 타입을 받아들이는지는 별도 확인이 필요합니다. UUID 문자열과 DB 열 타입, 시각의 offset, 결과 매핑은 실제 DB 통합 검증에서 확인합니다. 단위 테스트를 통과시키기 위해 필터 조건을 상수 값으로 대체하지 않습니다.

## 7. Spring 설정을 따라가기

`WebInitializer`부터 root와 web 설정을 나누어 그립니다. 서비스 생성자, Mapper 스캔, SqlSessionFactory, DataSource, TransactionManager가 어디에서 연결되는지 화살표를 추가하세요. Bean 대역 테스트와 실제 트랜잭션 실행 테스트의 차이도 표시합니다.
