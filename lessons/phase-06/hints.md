# Phase 6 — 단계별 힌트

JSTL 화면 작성 힌트는 [화면 실습 힌트](jstl/hints.md)에 따로 있습니다.

## 1. 누락과 잘못된 값 구분

Integer는 값이 없는 null을 표현합니다. 메서드에서 바로 산술 비교를 하면 자동 언박싱 시 어떤 일이 생기는지 확인하세요. 누락값은 기본 정책이고 0은 오류 입력입니다.

## 2. 경계를 먼저 확인

1과 200은 허용 범위의 양 끝입니다. 바로 바깥인 0과 201, Integer의 최솟값·최댓값을 각각 생각해 보세요. 값이 작거나 크다고 조용히 보정하지 않습니다.

## 3. 요청 사이 상태 없애기

기본값을 필드에 저장해 이전 요청이 바꿀 필요가 있는지 생각합니다. 같은 null 입력은 앞선 요청의 값과 관계없이 동일한 결과를 반환해야 합니다.

## 4. 오류 메시지도 계약

입력 오류를 설명하는 데 원본 값을 그대로 반환할 필요가 있는지 확인합니다. 실제 API의 오류 코드는 안전한 의미와 requestId를 제공하고 내부 예외를 숨깁니다.

## 5. 조회 역할 확인

DB 계정 이름, 연결 환경변수, GRANT 범위를 함께 읽습니다. readOnly Annotation과 DB 권한 검사는 같은 기능이 아닙니다. 실제 DB IT에서 쓰기 거절을 확인해야 합니다.

## 6. 테스트 대역이 대신하지 않는 것

Mockito가 반환한 DTO로 JSON 계약을 확인할 수 있지만 SQL의 날짜·UUID·권한이 맞는지는 별도 검증입니다. 거래 목록의 금액과 한도 사용액이 같은 업무 시점을 반영하는지도 SQL과 트랜잭션 범위에서 확인합니다.

## 7. 응답 크기 제한

최대 200건을 반환한다고 항상 빠른 검색이 되는 것은 아닙니다. 조회 조건과 정렬, 인덱스, 업무 날짜 범위를 함께 확인하세요. 다음 페이지 토큰을 구현하지 않은 계약에 페이지 이동을 가정하지 않습니다.
