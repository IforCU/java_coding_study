# Phase 1 — 단계별 힌트

아래 Maven 명령은 프로젝트 루트에서 실행합니다.

정답 코드와 완성 조건식은 이 문서에 포함하지 않습니다. 실패한 테스트를 한 묶음씩 읽고 정책의 어느 조건과 연결되는지 표시해 보세요.

## 1. 입력 오류와 정상 결과 나누기

null이 들어오면 금액 메서드를 호출하기 전에 처리할 필요가 있습니다. 이 실습의 오류 입력은 예외가 아니라 `false`입니다. 실제 `BankService`가 잘못된 거래에 업무 예외를 던지는 계약과 구분하세요.

## 2. 0원의 의미 구분하기

계좌 잔액 0원은 정상 상태입니다. 출금 요청 0원은 유효한 거래가 아닙니다. 잔액과 출금액에 동일한 양수 조건을 기계적으로 적용하지 않습니다.

## 3. 표현과 수치를 구분하기

`100`, `100.00`, `1E+2`는 표기가 다르지만 같은 금액입니다. scale만 보고 바로 거절하면 수학적으로 정수인 금액까지 거절할 수 있습니다. 반대로 정수로 변환하면서 소수부를 버리면 유효하지 않은 값을 허용하게 됩니다.

Java 17의 `BigDecimal` 공식 문서에서 수치 비교, scale, 정확한 변환과 반올림 관련 API를 찾아보세요. [BigDecimal 문서](https://docs.oracle.com/en/java/javase/17/docs/api/java.base/java/math/BigDecimal.html)

## 4. 정밀도 실패 재현하기

실습 테스트에는 `double`이 모든 정수를 정확하게 표현하지 못하는 범위의 값이 있습니다. 금액을 다른 숫자 타입으로 변환했다면 테스트가 그 변환을 왜 거절하는지 확인하세요. `long` 범위보다 큰 값도 같은 원칙으로 읽습니다.

## 5. 비교와 상태 변경 분리하기

정책 함수는 잔액을 소비하지 않습니다. 같은 검사를 연속 호출한 테스트가 실패한다면 불필요하게 상태를 저장하지 않았는지 살펴보세요. 입출금과 기록을 실제로 반영하는 책임은 정상 계좌 모듈에 있습니다.

## 6. 실행 대상을 확인하기

기본 `mvn -Dmaven.repo.local=.cache/maven-repository verify`는 미완성 실습을 실행하지 않습니다. 실습을 검증하려면 `exercise-phase1` 프로필과 starter 모듈을 선택해야 합니다. 정답 프로필은 스스로 구현한 뒤 비교할 때만 선택합니다.
