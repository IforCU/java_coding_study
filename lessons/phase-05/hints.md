# Phase 5 — 단계별 힌트

JSTL 화면 작성 힌트는 [화면 실습 힌트](jstl/hints.md)에 따로 있습니다.

## 1. 마스킹 전에 입력 계약 확인

허용 구분자를 제거하는 작업과 잘못된 문자를 거절하는 작업은 구분됩니다. Unicode 숫자나 모든 공백을 허용하는 정규식이 계약을 넓히지 않는지 확인하세요.

## 2. 길이와 마지막 네 자리

길이 검사는 구분자 제거 후의 값으로 수행합니다. 8자리와 20자리 경계를 먼저 확인하고, 앞자리 0을 잃을 수 있는 숫자 타입 변환을 검토합니다. 반환된 앞부분이 원문 숫자를 포함하지 않는지 확인하세요.

## 3. 오류 경로도 표시 경계

정상 반환값을 가렸어도 예외에 입력 원문을 넣으면 오류 응답이나 로그로 전달될 수 있습니다. 일반적인 오류 메시지와 trace ID로 조사할 수 있는지 확인합니다.

## 4. 거절한 계층 찾기

미인증, 권한 부족, CSRF 실패, 업무 입력 오류는 요청이 도달하는 지점이 다를 수 있습니다. 응답 상태만 보지 말고 Controller와 저장소에 부작용이 있었는지 확인하세요.

## 5. 세션 테스트에서 재인증 제거

로그인한 쿠키만 사용하는 요청과 HTTP Basic 자격 증명을 보내는 요청을 나눕니다. 세션을 없앴는데도 인증되는 경우 매 요청에 다시 인증할 정보가 포함되어 있는지 확인합니다.

## 6. 장애 랩의 PASS 읽기

기존 랩은 의도한 잘못된 결과를 관찰하기 위한 검증입니다. 원본 증상을 기록한 뒤 수정안의 기대 결과를 별도 회귀 검증으로 작성합니다. 정상 서비스에 문제를 켜는 옵션을 추가하지 않습니다.

## 7. 실행 환경과 원인 구분

DB 없이 실행하는 랩은 축소된 논리 재현입니다. 실제 풀 대기·SQL 취소·auto-commit은 PostgreSQL IT에서 확인합니다. 엔진 부재를 코드의 정상 동작 증거로 사용하지 않습니다.
