# 예전 JSP를 분석하는 연습

분석 대상은 [`legacy-customer.jsp.txt`](../../exercises/starter/phase-02/legacy-customer.jsp.txt)입니다. 의도적으로 여러 책임과 오류를 섞은 비실행 텍스트로, 정상 WAR에 포함되지 않습니다. 이 문서는 분석 순서와 기록 양식이며 완성 리팩터링 정답은 solutions에 있습니다.

## 먼저 읽을 기준 소스

정상 `modules/02-servlet-jsp`에서 `BankServlet`, `BankService`, `JdbcBankDao`, `WEB-INF/views/customers.jsp`를 순서대로 읽습니다. 요청 값이 어디에 들어오고 어떤 DTO가 화면에 전달되는지 연결합니다. 그다음 분석 텍스트와 비교합니다.

## 변경 전 기록 양식

| 항목 | 학습자가 작성할 내용 |
| --- | --- |
| 관찰된 증상 | 화면 오류, 잘못된 조회, 연결 부족 등 코드가 만들 수 있는 결과 |
| 관련 줄 | 입력·쿼리·응답·자원 처리 위치 |
| 실패 조건 | 정상 입력과 오류 입력에서 달라지는 경로 |
| 책임 경계 | 요청, 업무 규칙, DB, 표현 중 소유할 곳 |
| 변경 범위 | 바꿀 파일과 유지할 공개 동작 |
| 검증 | 성공·실패·반복 호출에서 확인할 결과 |

문제 이름부터 붙이기보다 데이터가 코드의 어떤 문자열과 자원으로 이동하는지 따라갑니다. 한 줄에서 여러 역할이 보이면 각각 분리해서 기록합니다.

## 검증 설계 질문

- 입력에 공백과 특수문자가 들어오면 같은 조회 목적이 유지되나요?
- 조회 중 예외가 발생해도 빌린 자원이 정리되나요?
- DB에 저장된 이름은 HTML에서 어떻게 표현되나요?
- 저장소 내부 오류가 브라우저에 어느 범위까지 전달되나요?
- 화면만 수정한 변화와 SQL만 수정한 변화를 독립적으로 검증할 수 있나요?

취약 코드의 배포나 실제 자격 증명 입력 없이 소스 분석과 대역 기반 테스트로 과제를 진행합니다. 정답 비교는 `exercises/solutions/phase-02/README.md`에서 명시적으로 선택합니다.
